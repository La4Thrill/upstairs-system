> 一切都在 `D:\KS\upstairs-system` 里。按顺序做，每步都有"看到什么算成功"。

## 一、硬件准备（提前 5 分钟）

| 步骤 | 做什么 | 成功的标志 |
|---|---|---|
| 1 | 5V 适配器插进板子**黑色圆孔**（`POWER IN`） | — |
| 2 | 按一下白色自锁开关 | **`POWER LED`（L3）亮** |
| 3 | USB 线插板子**中间**那个 Mini-USB 口（`UART-USB`） | 电脑出现 `USB-SERIAL CH340 (COM3)` |
| 4 | 九轴模块已按线接好（4 根：GND / 3.3V / SCL=PB6 / SDA=PB7） | 模块不烫、线没松 |

> ⚠️ 三个小口顺序：**最上面 JTAG（烧录用）、中间 UART-USB（串口用）★、最下面 USB-Slave**
> ⚠️ 红色跳线帽保持在 **`VIN`** 那一侧（用适配器供电）

## 二、启动（3 个窗口，顺序别乱）

### 第 1 步：起服务端

**双击**：

```
D:\KS\upstairs-system\cmake-build-debug\server.exe
```

会弹出一个黑窗口，应该看到：

```
[BOOT] Stair IoT server starting...
[DB] Database ready (stair.db).
[SIM] 2 simulated terminals ready (SIM-01=upstairs3, SIM-02=dailywalk)
```

**看到 `listening on :8080` 就算成功。这个窗口不要关**（关了服务就停了）。

## 三、演示流程（建议按这个顺序讲）

### ① 先看设备列表

「设备 / 采集通道」应该有三行：

| 设备ID | 来源 | 状态 |
|---|---|---|
| SIM-01 | 模拟终端 | 离线 |
| SIM-02 | 模拟终端 | 离线 |
| **STM32-01** | **真实设备** | **在线** ← 实时的 |

### ② 数据集回放（证明算法对）

在「模拟端控制台」里：

```
目标终端：全部终端
加载场景：上三层楼数据（判层）
```

点 **「加载文件」** → 点 **「开始」**

然后「当前查看」下拉选 **`SIM-01`**，看「爬楼结果」：

| 指标 | 约 50 秒后 |
|---|---|
| 当前楼层 | **4** |
| 已爬楼层 | **3** |
| 总台阶数 | **68** |
| 步频 | **~82 级/分** |
| 中间平台数 | **3** |

> 这组数字来自老师的数据集，是"标准答案"。

### ③ 真机演示（证明能落地）

「当前查看」切到 **`STM32-01`**，然后把板子拿起来：

```
单手握板（屏幕朝外） → 走一段平路 → 上一层楼梯
```

**现场应该看到：**
- 页面上「总台阶数」一个数一个数往上涨
- 「当前楼层」从 1 变成 2
- 板子上的**蜂鸣器每级台阶响一声**，到一层时 LED1 翻转
- 下面「波形验证」三条曲线跟着动

### ④ 重置再走一遍（可选，很加分）

点「设备 / 采集通道」右上角的 **「重置当前设备」** → 台阶和楼层归零 → 再走一段。

对比"重置前 / 重置后"两张截图，能说明系统是可重复使用的。

### ⑤ 对比讲解

来回切换「当前查看」：`SIM-01`（数据集）↔ `STM32-01`（真机）

一句话总结：**"同一套算法，既能在老师的数据集上跑出 3 层，也能在真实传感器上跑出来。"**

## 四、当场出问题怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 网页打不开 | 服务端没起 / 窗口被关 | 重新双击 `server.exe` |
| 设备列表没有 STM32-01 | 串口桥没起 | 重新双击 `run-ingest.bat` |
| 有 STM32-01 但显示"离线" | USB 松了 / 板子没电 | 看 `POWER LED`，重插 USB，等 3 秒点「刷新设备」 |
| 数据不动、台阶不涨 | 九轴模块线松了 | 断电重插模块的 4 根线 |
| 数字乱跳 / 一直归零 | 串口被别的程序占用 | 关掉任何 XCOM / SSCOM / 串口助手 |
| 想一键恢复 | 重启服务端 | 双击 `tools\reset-real-device.bat` |

**保命操作**：实在不行就全部关掉 → 先启 `server.exe` → 再启 `run-ingest.bat` → 刷新网页。30 秒能恢复。

## 七、可靠性设计（这两天踩过的坑，都已修）

真实联调时反复出现"一会儿有数据、一会儿设备离线"，最后定位到 **4 个独立问题**，
每一个都会在演示时致命：

| # | 问题 | 现象 | 修法 |
|---|---|---|---|
| 1 | `for raw in src` 迭代 pyserial 的 `Serial` | 串口只要 **1 秒**没数据，`readline()` 超时返回 `b''`，迭代器当成 EOF → **采集进程静默退出** | 改成 `while True: raw = src.readline()`，空结果 = 超时，继续等（每 30 s 提示一次） |
| 2 | `serial.Serial(port, baud)` 默认 assert DTR | 板子的 CH340 接了"一键下载"电路（DTR→RESET），MCU 可能被**按在复位里** → 端口能开、永远读到 0 字节 | 显式 `dtr=False; rts=False` 后再 `open()` |
| 3 | 固件 `if (!Probe()) { while(1) 闪灯; }` | 上电瞬间模块没就绪 → **永久静默**，只能彻底断电重来 | 改成每秒重试，打印 `[WAIT] ...`，模块一插好自动开始采集 |
| 4 | 串口桥 HTTP 失败直接 `SystemExit(3)` | 服务端重启一次，桥就死，设备立刻离线 | 每 0.5 s 重试、最多 30 秒；连不上只丢当前批、进程不退 |

### 修复后的自愈能力（现场最能体现价值的地方）

| 意外 | 以前 | 现在 |
|---|---|---|
| 板子晃了一下，模块线松了 | 整场报废，必须断电重来 | 1 秒内自动重试成功，观众看不出来 |
| 服务端崩了/你要重启 | 桥跟着死，得重开窗口 | 桥自动重连，最多等 30 秒 |
| USB 被碰掉一下 | 桥崩 | 检测到异常 → 2 秒后重连串口 |
| 串口刚好 1 秒没数据 | 桥静默退出 | 继续等，每 30 秒提示一次 |

### 顺带发现：供电也要稳

板子的 **DC 电源座是 5.5×2.1mm，配的适配器插头是 5.5×2.5mm**，接触不可靠。
插头一晃就断电，断电重启时如果模块还没就绪（问题 3），就会进入静默状态。

**建议演示前**：
- 把 DC 插头插到底、左右转一下确认接触
- 或者把 `J6` 跳线换到 `VBUS`，**只用 USB 供电**（一根线最省事，也避免 DC 座松动）

### 自查口诀

```
设备"离线"但 POWER LED 亮
  → 先看串口有没有在刷数据（串口助手 / run-ingest 窗口）
     有数据 → 服务端/密钥问题
     没数据 → 固件在 [WAIT] 重试（模块线松）或卡住 → 按 RST；还不行就彻底断电
```
